# 为什么从 Windows 迁移

> 记录日期：2026-10-20。阶段：Phase 1，Docker 安装之前。

返回 [项目首页](../README.md)。

## 迁移开始的时候，桌上有两台电脑

一台是每天都在用的 Mac。M4，24GB 统一内存，512GB SSD。写代码、改文档、开终端，都在这里。它不需要被重装，它的新职责是当远程管理端。

另一台是联想小新 Pro 16，2021 款。16GB 内存，1TB SSD，4GB 显存。它跑着 Windows，里面已经装过 WSL2 和 Docker，也堆着 IDE、课程文件和一些试过就放下的环境。系统还能用，只是越来越不像一台我愿意继续维护的开发机。存储使用情况也不理想。

还有一个硬件事实：这块笔记本的内屏坏了。很长一段时间里，它靠一块 AOC 外接显示器显示 Windows 桌面。

我想要的新角色很具体。这台小新以后长期开着，当一台服务器。Mac 在需要的时候连进去。它不再承担日常桌面。

## 两条路

**方案 A：重装一个干净的 Windows，再把一部分资源分给 WSL2。**

这条路我认真考虑过。WSL2 可以正常运行 Docker，也可以运行 Linux 开发工具。如果这台电脑的主身份仍然是 Windows 工作站，顺便需要一个 Linux 环境，方案 A 足够。

**方案 B：清除 Windows，安装原生 Linux。**

最后选了 B。原因不是“WSL2 不能用”，而是这台机器的主身份变了。

- Windows 几乎已经不用。为了一个很少打开的桌面，继续保留整套宿主，不值得。
- 服务器要长期开着。原生系统里，开机、网络、SSH、合盖，都是主机自己的 systemd 在管。WSL2 再完整，前面仍然站着一个 Windows 宿主，宿主休眠或更新，客机就跟着停。
- 内屏是坏的。图形桌面离不开外接显示器。Ubuntu Server 的文本终端加上 SSH 之后，显示器可以收起来。
- 旧环境已经乱。与其在原系统里再隔一层，不如先把重要文件备份走，再把整块 SSD 交给新系统。

备份在重装之前已经完成。后面的清除是在这个前提下做的。

## 原生 Linux 适合这个场景的地方

把“服务器”理解成一组长期运行的进程，就比较容易看出差别。

WSL2 是 Windows 里的一个 Linux 环境。它适合开发：编辑器在 Windows，工具链在 Linux，两边共享文件。这个能力是真实的。这次迁移没有否定它。

这台小新要做的事是另一份工作：没人坐在它前面时，它也得在线上；Mac 通过 SSH 进来；合上盖子不能把机器带去睡觉；校园网认证掉了要有机会自己查。这些事情的控制点都在主机固件、主机网络和主机 init 系统上。让 Ubuntu 直接当主机，控制点就只有一层。

内屏损坏把这个判断推得更明确。一台还想当 Windows 桌面的电脑，坏屏幕是残废。一台准备当无头服务器的电脑，坏屏幕只是少了一个本地显示器。前提是安装的那一下得能看见启动菜单。那一下后来确实卡住了，记在 [坏屏幕与启动菜单](03-headless-display-troubleshooting.md)。

## 这次没有顺便做的事

选方案 B 的时候，没有同时规划显卡驱动、容器平台或对外发布的网站。那些如果要做，属于以后的阶段。Phase 1 的完成线画在这里：系统能启动，网络能通过校园网认证到达互联网，Mac 能用 `ssh xin-server` 登进来，合盖和升级重启之后这条路还在。

Docker 是下一阶段的第一件事，不是这一篇里的隐藏步骤。
