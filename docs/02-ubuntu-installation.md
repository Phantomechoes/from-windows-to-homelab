# Ubuntu 安装

> 记录日期：2026-10-20。阶段：Phase 1，Docker 安装之前。
> 主机名 `xin-server`，用户 `dev`，系统 Ubuntu Server 26.04.1 LTS，amd64。

返回 [项目首页](../README.md)。上一篇：[硬件与架构](01-hardware-and-architecture.md)。

## 先说清楚这是破坏性操作

安装器使用了整块内置 SSD。Windows 分区在这一步被清除。清除之后没有回收站，也没有这次记录里的系统级回滚。

重要文件在进入安装器之前已经备份。没有备份，就不到这一步。

也不需要先在 Windows 里做“重置此电脑”。安装介质自己能启动时，可以直接从 U 盘进入 Ubuntu 安装器，在安装过程中处理旧系统。重置会多花一轮时间，还是停在即将被擦掉的系统里。

## 安装盘

| 项目 | 这次的选择 |
| --- | --- |
| 镜像 | Ubuntu Server 26.04.1 LTS，amd64 |
| 介质 | 32GB U 盘 |
| 制作环境 | 即将被替换的那台 Windows |
| 工具 | Rufus 4.15 |
| 分区类型 | GPT |
| 目标系统 | UEFI，非 CSM |
| 文件系统 | FAT32 |
| 持久化分区 | 不配置 |

Rufus 写完后显示 Ready。持久化分区是给“把 U 盘当随身系统”用的。这次 U 盘只负责把安装器送进内存，写完就结束，所以没有做持久化。

CSM 是传统 BIOS 兼容模式。这台机器走 UEFI。安装器后面会要一块 EFI 系统分区，启动方式需要和它一致。

## 进入安装器之前

坏屏把启动菜单藏了一段时间。U 盘插上并不等于能看见 `Try or Install Ubuntu Server`。显示排查单独写在 [坏屏幕与启动菜单](03-headless-display-troubleshooting.md)。下面从已经看见 GRUB、并进入安装器之后开始。

## 安装器里的选择

| 项目 | 选择 | 原因 |
| --- | --- | --- |
| 语言 | English | 安装器和以后的系统消息用英文，搜索报错时和文档用词一致 |
| 键盘 | English (US) | 与语言一起选定 |
| 系统形态 | Ubuntu Server，不选 minimized | 保留标准服务器软件集合。最小化安装能再省一点空间，这台机器的磁盘不是瓶颈 |
| 第三方驱动 | 暂时不装 | Phase 1 没有计划用专有驱动 |
| Wi-Fi | 跳过，离线安装 | 安装阶段这块无线网连不上可用网络。硬等它，安装会停在网络页 |
| 代理 | 保持默认 | 没有额外代理 |
| Ubuntu Pro | 跳过 | 当时不需要 |
| 磁盘 | 使用整块内置 SSD | 这台机器改当服务器，不再保留 Windows |
| LVM | 取消 | 单盘服务器，先要一块看得懂的分区 |
| LUKS | 不启用 | 这次没有做磁盘加密。以后若要加密，需要单独设计解锁方式，无头机器尤其要先想清楚 |
| OpenSSH | 勾选 Install OpenSSH server | 装完就有 SSH 服务，不必再找显示器装一遍 |
| SSH 登录 | 允许初期使用密码 | 密钥是后来从 Mac 放上去的。密码是第一条远程入口 |

安装语言选英文，不影响这个仓库用中文写。它只影响系统自己的界面和报错文本。

离线安装的后果会在第一次启动时出现：机器上还没有一份可用的网络配置，systemd 仍会等网络。见下文。

## 磁盘布局

| 分区 | 大小 | 文件系统 | 用途 |
| --- | --- | --- | --- |
| EFI | 约 1GiB | FAT32 | UEFI 启动 |
| `/` | 约 930GiB | ext4 | 根文件系统 |

没有 LVM，也没有 LUKS。数字是安装时看到的大约值，不是事后用 `lsblk` 重新测量的精确字节。1TB 的盘在十进制容量和 GiB 换算之后，扣掉 EFI，根分区落在这个量级。

## 身份

- 服务器名称：`xin-server`
- Linux 用户：`dev`

这两个名字会反复出现在提示符和 SSH 配置里。它们是这台机器的名字，不是校园网账号。

## 安装完成

安装日志的最后一屏是：

```text
Installation complete!
```

到这里，Windows 已经不在这块 SSD 上。后续的启动目标是新写入的 Ubuntu。

## 第一次启动

重启时发生了三件叠在一起的事。

内外屏有一段时间没有正常输出。坏屏加上还没稳定的早期显示，又黑了一阵。这和安装前固件菜单的问题是同一类现象：操作系统还没把外接显示管起来之前，不要假设“刚才安装器能看见，重启后每一秒都能看见”。

systemd 走到网络等待，出现 `network wait-online`。安装时跳过了 Wi-Fi，系统里没有一份已经连上的网络，等待就拉长了。等待结束之后，启动继续往下走。网络等待拖时间，不等于安装失败。

最后，本地控制台进入 tty1 的登录界面。用安装时创建的 `dev` 登录，提示符是：

```text
dev@xin-server:~$
```

Ubuntu Server 默认就是这个文本终端。没有桌面、没有任务栏、没有文件窗口，是这款镜像的设计，不是安装器少装了一个组件。日常操作是在 shell 里输入命令，管理权限用 `sudo`。需要图形界面的工作留在 Mac 上。

本地登录这一步很重要，因为当时远程还不可用：无线网还没配，Tailscale 还没装，Mac 也还不知道该连哪个地址。tty1 是那一段时间里唯一的键盘。

网络从这里才开始配。下一篇先把“怎么看见安装器”补完，再进入校园网：[坏屏幕与启动菜单](03-headless-display-troubleshooting.md)。
