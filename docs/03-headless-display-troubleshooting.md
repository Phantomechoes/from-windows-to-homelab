# 坏屏幕与启动菜单

> 记录日期：2026-10-20。阶段：Phase 1，Docker 安装之前。

返回 [项目首页](../README.md)。上一篇：[Ubuntu 安装](02-ubuntu-installation.md)。

系统还没开始安装，我就先被一块坏掉的屏幕挡在了 BIOS 门口。

## 一块屏幕，两种表现

小新 Pro 16 的内屏是坏的。Windows 已经启动、桌面加载完成之后，AOC 外接显示器可以正常工作。所以在很长一段时间里，这台电脑“看起来没问题”：插上显示器，就能看见 Windows。

UEFI 和早期启动不是桌面。固件菜单、启动设备列表、GRUB，发生在操作系统把显示驱动管起来之前。USB-C 转 HDMI 或 DisplayPort 的那路外接显示，在这段时间里没有稳定画面。

这件事容易误判。桌面能亮，只说明 Windows 图形栈认识那路输出。它不证明固件也认识。安装 Linux 的第一眼，恰恰要看固件。

这次没有拆机，也没有换屏。排查都在开机热键、Windows 高级启动和换显示接口这几件事里面。

## 实际做过的尝试

按发生的顺序：

1. 开机后连续按 F12，以及 Fn + F12，想进入联想的启动设备菜单。
2. 从仍能使用的 Windows 桌面进入高级启动，打开“使用设备”，尝试从 EFI USB Device 启动。
3. 更换外接显示的接法，改用笔记本自己的 HDMI 口。
4. 在这之后，外接显示器上出现了联想的启动设备菜单，以及后来的 Ubuntu GRUB。

前两步是在 USB-C 转接的画面仍然不可靠时做的。第 3 步更换了信号出口。第 4 步是看见菜单的结果。这几步都做过。文档不把其中一次按键写成唯一原因，只保留这个顺序：原生 HDMI 接上之后，启动菜单变得可见。

Windows 高级启动里的“使用设备”是另一条路。它不依赖开机瞬间那一下 F12 是否被按中。当时 Windows 还在，这条路可以试。等 SSD 上的 Windows 被清掉，这条路也就没有了。以后如果再重装，入口只剩下固件菜单，显示得在那之前就准备好。

## 菜单里不只有 U 盘

启动设备菜单里有多条旧记录。看见过的包括：

- Windows Boot Manager
- ubuntu（SSD）
- Linpus lite（SSD）
- Linpus lite（USB 设备）

名字会骗人。`ubuntu` 和 `Linpus lite` 都出现了不止一种位置。这次没有去追这些旧记录是哪一次安装留下的。选择时看的是位置：要启动的是 U 盘，就选标成 USB 设备的那一项，而不是 SSD 上的同名或相似项。

选中 USB 设备之后，出现了 GRUB 菜单：

```text
Try or Install Ubuntu Server
```

从这里进入 Ubuntu Server 安装程序。安装器里的选项见 [Ubuntu 安装](02-ubuntu-installation.md)。

## 重启时画面还会再丢一次

安装完成、第一次重启时，内外屏又短暂没有正常输出。然后 systemd 在没有可用网络的情况下等待 `network wait-online`，最后才到 tty1。

所以“安装器能看见”和“每一次重启的前几秒都能看见”不是同一件事。本地显示器是安装和排障时的工具。安装完成、SSH 可用之后，它不再是日常入口。重启后本地 tty1 停在登录提示，远程会话仍然可以单独存在。这一点在升级重启时又验证了一次，见 [系统更新与重启](08-system-maintenance.md)。

## 值得记住的判断

- 外接显示器在桌面里亮着，不能证明固件菜单会在同一路输出上亮着。
- 笔记本自带的 HDMI，和 USB-C 转接出去的显示，对固件来说可以是两条完全不同的路。
- 启动菜单按“USB 还是 SSD”来读，不按品牌名字来读。
- 无头是 SSH 配好之后的运行方式。在那之前，至少要解决一次“看得见 GRUB”。
